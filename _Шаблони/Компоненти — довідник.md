# Компоненти презентації для класу

Це правила для того, хто робить новий урок — людини або моделі.

## Порядок дій. Коротко

1. **Спершу подивись, що вже є.** Ніколи не починай з написання власної верстки.
   ```
   python3 tools/components.py            # список із описами й де подивитись приклад
   python3 tools/components.py --markup   # одразу з готовою розміткою
   ```
   Або просто відкрий у браузері `_Шаблони/Презентація для класу — шаблон.html` —
   це живий каталог: кожен компонент там показано в роботі.

2. **Візьми готове.** Скопіюй розмітку з шаблону й заміни числа й текст.
   Нічого дописувати в `<style>` чи `<script>` уроку не треба — двигун
   уже вбудований у кожен дек.

3. **Своє пиши, тільки якщо справді нічого не підходить.** Тоді — за правилами
   з розділу «Як додати новий» нижче.

4. **Перевір.**
   ```
   python3 tools/check_decks.py --only "5-З/Математика/Уроки/Урок 12"
   ```
   Перевірка ловить помилки скрипта, компоненти, які не побудувались,
   і слайди, що не влазять в екран на 1440×900 і 1280×720.

## Де що лежить

| Файл | Що це |
|---|---|
| `_Шаблони/Двигун — стилі.css` | усі стилі. **Єдине джерело.** |
| `_Шаблони/Двигун — скрипт.js` | уся логіка. **Єдине джерело.** |
| `_Шаблони/Презентація для класу — шаблон.html` | заготовка уроку + живий каталог |
| `tools/update_decks.py` | вбудовує двигун у всі деки |
| `tools/check_decks.py` | перевіряє деки в headless Chrome |
| `tools/components.py` | друкує список доступного |

Двигун **вбудовується** в кожен дек, а не підключається посиланням: презентація
має відкриватися як один самодостатній файл — і подвійним кліком з диска,
і з GitHub Pages. Тому після правки двигуна обовʼязково:

```
python3 tools/update_decks.py     # перенести зміни у всі 41 дек + шаблон
python3 tools/check_decks.py      # переконатися, що нічого не зламалось
```

Правити `<style>`/`<script>` усередині окремого дека **не можна** — наступний
`update_decks.py` затре. Блок `/*=LESSON-CSS=*/` — єдине місце в деку,
куди можна дописувати стилі, і тільки для того, що потрібне саме цьому уроку.

## Як додати новий компонент

Роби це, лише коли жоден наявний не підходить — не «схожий, але хочу інакше»,
а справді немає чим показати потрібне.

1. **Спитай себе, чи це справді новий компонент.** Якщо йдеться про єдиний
   малюнок для однієї задачі — це не компонент. Це `/*=LESSON-CSS=*/` цього уроку
   (так живуть `.sc` — терези, `.flow` — схема, `.scheme` — таблиця розрядів).
   Компонент — це те, що знадобиться ще хоча б двічі, в інших уроках.

2. **Назви так, щоб не збігалося з наявним.** Перевір:
   `python3 tools/components.py` і пошук по `Двигун — стилі.css`.
   Зайняті короткі імена: `.ov` (овали в уроці 11), `.step` (крок розвʼязання),
   `.nl` (стара числова пряма), `.lt`, `.cw`, `.sc`.

3. **Пиши в обидва файли двигуна, а не в урок:**
   - стилі → `Двигун — стилі.css`, у свою секцію з коментарем-заголовком;
   - логіку → `Двигун — скрипт.js`, у вигляді `$$('.новий').forEach(function(box){ … })`,
     щоб `tools/components.py` побачив компонент сам.

4. **Дотримуйся правил двигуна:**
   - розміри через `clamp(мін, calc(k*var(--u)), макс)`, ніколи не в чистих `px`;
   - кольори тільки зі змінних (`--pen`, `--check`, `--marker`, `--sun`, `--note`, `--nb`) —
     жодних власних `#hex`, інакше зламається темна тема й режим проєктора;
   - те, що зʼявляється по пробілу, ховається `opacity`, **не** `display`:
     інакше висота слайда стрибає й автопідгін рахує не те;
   - після зміни висоти компонента виклич `fit()`;
   - нічого не вантаж із мережі: ні шрифтів, ні бібліотек, ні картинок.

5. **Покажи його в шаблоні** — додай слайд у
   `_Шаблони/Презентація для класу — шаблон.html`. Без цього
   `tools/components.py` попередить «у шаблоні не показано», і наступного разу
   компонент просто не знайдуть.

6. **Опиши** у словнику `WHAT` в `tools/components.py`: що це і **коли** брати.

7. **Розкоти й перевір:**
   ```
   python3 tools/update_decks.py
   python3 tools/check_decks.py
   ```

## Перемикачі вигляду

Ставляться атрибутом на `<html>`; учитель може змінити їх у деку клавішею `?`,
і вибір запамʼятовується.

| Атрибут | Значення | Що робить |
|---|---|---|
| `data-subject` | `math` `algebra` `geometry` `informatics` | тон палітри предмета |
| `data-fx` | `slide` `lift` `page` `fade` `none` | характер переходу між слайдами |
| `data-cards` | (немає) `now` `tab` | мʼякі / рамкою / наліпкою |
| `data-bg` | (немає) `dots` `lines` `plain` | клітинка / крапки / лінійка / чисто |
| `data-theme` | (немає) `light` `dark` | тема; немає — як у системі |
| `data-proj` | `1` | режим проєктора: чорне на білому, товщі лінії |
| `data-class-size` | число | скільки учнів у класі — звідси діапазон для «випадкового номера» |

## Два типи завдань, які видно кольором

Це не оформлення, а правило — учень має бачити, що робити, не питаючи.

| Розмітка | Колір | Значення |
|---|---|---|
| `class="box nb"` | бірюзова суцільна рамка, плашка **✎ у зошит** | переписуємо в зошит |
| `class="box oral"` | малинова **штрихова** рамка, плашка **🗣 усно** | тільки проговорюємо, не пишемо |

Так само працюють `tbl nb` / `tbl oral` (таблиця), `fig nb` / `fig oral` (малюнок),
`span.nbw` / `span.orw` (окреме слово в тексті). Обидва кольори віддані під ці
два значення й **більше ніде не вживаються** — інакше сигнал перестає працювати.
Рамка штрихова навмисно: різницю видно й на роздруківці, і в режимі проєктора.

Не позначати жодним із них: умову задачі, підказки, «типова помилка», «цікаво», прикидку, паузи.

## Обовʼязкове в кожному уроці

**У кожному уроці має бути щонайменше одне завдання з випадковим номером.**
Форма будь-яка: усно, вголос із місця, чи в зошиті з відповіддю в кінці —
але завдання, де відповідає не бажаючий, а той, чий номер випав, має бути.

Це перевіряється: `python3 tools/check_decks.py` позначає дек, у якому немає
жодного `.mode.pick` чи `.roster`.

**Кожна вправа, яку учні вирішують самі в зошиті, має сказати, хто відповідає.**
Тобто на слайді, де `nb`-блок має приховану відповідь (`box nb hide` або `.hide`
всередині `box nb`), у смужці `.modes` обовʼязково стоїть `<span class="mode want">`
(відповідає бажаючий) **або** `<span class="mode pick">` (випадковий номер).
`mode book` каже, *куди* писати, `mode voice` і `mode cam` — *як* показати; жоден з них
не каже, *хто* відповідає, тож самі по собі вони цю вимогу не закривають — додаємо до них
`want` або `pick`.

Це теж перевіряється: `check_decks.py` перелічує слайди «вправа у зошит без способу
відповіді». Самостійною роботою вважається слайд, де є будь-що з трьох: `nb`-блок
із прихованою відповіддю, чип `mode solo`, або «у зошит» + `data-timer` + прихована
відповідь будь-де на слайді.

**Слайд, де пояснює вчитель, позначається `<span class="mode listen">слухаємо пояснення</span>`.**
Це єдиний чип, де учні нічого не відповідають, — тому він навмисно сірий, без свого кольору.
Він же знімає вимогу «хто відповідає»: якщо на слайді стоїть `listen`, `check_decks.py`
не просить там `want`/`pick`.

## Випадковий номер

Чип `<span class="mode pick">` у смужці «як відповідаємо» — **сам кнопка**:
тицяєш, номер прокручується й зупиняється. Діапазон 1…N береться з `data-class-size`
на `<html>` (або `data-to` на самому чипі). У межах кола номер не повторюється.
Для окремого слайда є велика версія — `<div class="roster">`.

## Клавіші під час уроку

`пробіл` `→` далі · `←` назад · `O` огляд слайдів · `T` таймер завдання ·
`U` таймер уроку (`Shift+U` — спочатку) ·
`D` маркер · `L` лазер · `C` стерти · `B` затемнити екран ·
`F` весь екран · `Y` тема · `P` проєктор · `?` довідка й друк.

## Загальний таймер уроку

Чип `УРОК 40:00` у шапці — двигун додає його сам, у розмітці нічого писати не треба.
Лічить **до дзвінка**: стартує з першого гортання слайда, останні 5 хв бурштинові,
після дзвінка червоний із «−». Клік або `U` — пауза/продовжити, подвійний клік
або `Shift+U` — спочатку. Інша тривалість — `data-lesson="35"` на `<html>`.
Основна лінія уроку планується на **35 хв** із 40.
